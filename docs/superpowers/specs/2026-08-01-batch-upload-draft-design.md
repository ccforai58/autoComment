# 批量导入草稿持久化设计

## 目标

普通 CSV 与 Semrush CSV 成功导入后，在用户尚未启动批量任务时也可靠保留预览列表；页面刷新或重新打开后恢复该列表。

## 现状与根因

批处理页的 `parsedUrls` 只存在页面内存。现有运行状态仅在点击“开始批量任务”后写入，因此未启动的导入在刷新或扩展页面重建后丢失。

## 方案

新增独立的“待启动导入草稿”状态，保存在 `chrome.storage.local`，并按当前推广网站隔离。草稿只表示已成功解析、尚未执行的导入，不复用正式批量任务运行状态。

草稿包含：版本号、导入类型、文件名、文件内容指纹、解析后的 URL 项、显示统计和保存时间。不会保存原始文件内容或任何凭据。

## 行为规则

1. 普通 CSV 或 Semrush CSV 完成解析并得到有效列表后，先写入草稿，再显示导入完成状态。
2. 页面初始化时，若当前推广网站没有可恢复的正式运行任务，则恢复对应草稿并重建预览、文件信息和统计。
3. 新文件只有在解析成功后才替换当前草稿。格式错误、空文件或 Semrush 处理失败不得覆盖原有草稿。
4. 再次导入内容指纹相同的文件时，保留现有草稿和列表，不重复写入 URL，并提示该文件已导入。
5. 用户点击“移除文件”时删除当前推广网站的草稿；点击“开始批量任务”后删除草稿，后续由正式运行状态保存进度。
6. 草稿仅用于未开始任务；恢复草稿必须保持 `idle` 状态、不可显示为已终止任务，也不得影响历史任务恢复。

## 错误处理与日志

草稿写入失败时保留当前页面预览，并向控制台输出不含 URL 全文或文件内容的结构化失败日志。恢复失败时不阻断页面加载，继续按现有正式任务恢复逻辑执行。

## 测试

为纯函数增加单元测试：草稿构建与版本/推广站校验、同指纹重复识别、不同文件替换判定、从草稿恢复为 idle 状态。页面脚本测试确认草稿存储键和恢复/清理调用已接入。
