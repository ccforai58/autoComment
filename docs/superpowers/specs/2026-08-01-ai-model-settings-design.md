# AI 模型配置页面设计

## 目标

为本地扩展增加独立的 AI 模型配置页面，使用户可以在不编辑文件的情况下配置任意 OpenAI 兼容模型，并在保存后执行真实连通性测试。默认提供 PackyAPI 的 DeepSeek 配置，保持现有启动检测与评论生成流程可用。

## 页面与导航

首页增加“AI 模型配置”入口，点击后打开 `model-settings.html`。页面包含：

- 服务商预设：PackyAPI / 自定义兼容接口。
- API 基础地址、请求模式、请求路径、模型名和令牌输入框。
- PackyAPI 预设：基础地址 `https://www.packyapi.com/v1`，请求模式 `chat_completions`，请求路径 `/chat/completions`，模型名由用户选择或填写 DeepSeek 可用模型名。
- 保存按钮和“测试连通性”按钮。
- 配置状态、模型响应耗时和经过脱敏的错误提示。

令牌输入框仅在用户输入时保存，不从后端回显。已保存令牌只显示为掩码与“已配置”状态。

## 配置保存

新增后端模型配置服务，统一读取当前运行时配置。保存接口验证基础地址、路径、模型名和令牌非空，然后把配置写入本机、被 Git 忽略的 `.env` 文件，并同步更新当前 Node 进程的 `process.env`。

保存和状态接口绝不返回、记录或显示完整令牌。日志只允许记录服务地址的主机名、模型名、请求模式、成功状态、耗时与脱敏错误代码。

## 连通性测试与启动检测

测试接口使用当前保存的配置向目标模型发送极短的 `ping` 请求：chat-completions 使用一条最小 messages 请求，responses 使用最小 input 请求。接口验证 HTTP 成功状态和可提取的文本响应，返回成功、耗时、模型名和简短响应摘要；失败返回脱敏错误。

服务启动时读取配置并异步执行相同的真实检测，记录最近一次状态但不阻塞 HTTP 服务监听。`/api/local-status` 保留当前数据库检查，并返回模型的配置状态、实际可用状态、最后检测时间和安全错误摘要。模型状态过期时，状态接口触发后台刷新，避免每次页面刷新都消耗模型额度。

## 兼容与验证

现有 `MODEL_*` 环境变量继续作为唯一运行时配置来源；配置页只是安全地维护本机 `.env`。现有生成请求无需变更调用方。

新增纯逻辑和 API 测试，覆盖 PackyAPI 预设、令牌掩码、`.env` 更新、chat-completions 与 responses 测试请求、失败脱敏、启动状态和配置页脚本。浏览器验证保存配置、测试连通性和启动状态显示。
