# 批量任务管理设计

## 目标

将未启动导入草稿与已启动批量任务分离。用户暂停任务 A 后，可以导入并启动任务 B；已完成和暂停任务持续保留，直到用户手动删除。一次只允许一个批量任务处于运行状态。

## 数据模型

- 草稿继续使用现有项目 ID / URL 兼容键，仅保存未启动导入。
- 每个已启动任务拥有稳定 `batchId`，完整运行快照按该 ID 单独保存。
- 任务索引只保存名称、推广项目、状态、进度、时间和计数，用于任务页快速列表。
- 旧的当前任务快照继续保留为兼容读取路径；首次读到后迁移为独立任务快照。

## 交互

- 工作台默认恢复最近一次可恢复的当前推广项目任务；没有任务时恢复草稿。
- 任务页列出运行中、已暂停和已完成任务。选择任务后在工作台显示其进度和结果；暂停任务可继续。
- 正在运行时禁止切换或删除该任务，且外链检测按钮禁用并有简短悬浮说明。
- 暂停任务的“未执行”网址只显示“尚未提交”，不进入外链检测范围，也不计为失败。
- 已完成任务永久保留，仅用户手动删除；删除只移除该任务的本地快照和索引，不删除已同步的历史提交记录。

## 安全与兼容

- 快照不记录令牌、Cookie 或原始导入文件。
- 日志仅记录任务 ID、状态、数量和推广域名。
- 保留已验证的提交、暂停续跑和反链检测实现，仅在其外层加入任务注册和选择。
